# Контрактные упражнения

Сначала запустите исходный проект и получите `PASS` для живой проверки. Каждый кейс ниже создаёт независимую копию командой `python scripts/prepare_case.py <имя>`; после подготовки работайте в `.work/<имя>`. Изменяйте только файлы этой копии.

| Кейс | Что исследовать | Что наблюдать |
|---|---|---|
| `status` | Код ответа `POST /orders` в YAML | Документ валиден, но контракт не описывает фактический `201` |
| `type` | Тип `quantity` в схеме ответа | Живой JSON содержит число, а YAML требует другой тип |
| `required` | Обязательное поле в схеме заказа | Проверка указывает на отсутствующее свойство |
| `conflict` | Описание `409` при повторном `external_id` | Текст контракта расходится с сообщением реального ответа |
| `final` | Новое требование к `external_id` и схема ответа | После исправления схемы проявится расхождение в обработчике |

Для каждого кейса: выполните `python scripts/validate_spec.py spec/openapi.yaml`, запустите сервер **из копии**, выполните `python scripts/check_contract.py --spec spec/openapi.yaml --base-url http://127.0.0.1:8001`, прочитайте конкретный `FAIL`, измените контракт и повторите ту же проверку до `PASS`. В `final` новое правило требует, чтобы `external_id` начинался с `ORD-`; после правки `app/rules.py` перезапустите сервер. Итог — тот же сетевой запрос проходит и исходный baseline остаётся исправным.

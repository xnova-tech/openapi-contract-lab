# OpenAPI Contract Lab

Локальный сервис заказов и отдельный OpenAPI 3.1-контракт. Проект XNova позволяет изменить YAML и увидеть, проходит ли он проверку на **реальных HTTP-ответах**. Для работы не нужны Docker, база данных, аккаунт GitHub или внешний API.

## Получить проект

На странице шаблона можно выбрать **Code → Download ZIP** и распаковать архив. Если нужен свой Git-репозиторий, используйте **Use this template**. Оба пути дают одинаковые исходники. Нужен Python 3.12.

Откройте терминал в корне распакованного проекта. Создайте окружение и установите закреплённые зависимости:

```sh
python -m venv .venv
```

В macOS/Linux активируйте окружение командой `source .venv/bin/activate`, в PowerShell — `.venv\Scripts\Activate.ps1`. Затем установите зависимости:

```sh
python -m pip install -r requirements.txt
```

В командах ниже `python` означает Python из этого окружения. Если команда запускает другую версию, используйте путь к интерпретатору окружения напрямую.

## Проверить исходный контракт

В первом терминале запустите сервер:

```sh
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/docs`: Swagger UI читает авторский `spec/openapi.yaml` через `/openapi.json`. Запрос `http://127.0.0.1:8000/health` должен вернуть `{"status":"ok"}`.

Во втором терминале, из того же каталога и окружения, выполните:

```sh
python scripts/validate_spec.py spec/openapi.yaml
python scripts/check_contract.py --spec spec/openapi.yaml --base-url http://127.0.0.1:8000
python -m pytest -q
```

Первая команда проверяет OpenAPI 3.1, локальные `$ref` и JSON Schema. Вторая посылает настоящие GET/POST/PATCH-запросы запущенному серверу и сверяет статус, `Content-Type`, JSON Schema и описание ошибок. Ожидаются `VALID`, 13 строк `PASS` и успешный pytest. Остановите сервер в первом терминале сочетанием `Ctrl+C`.

## Практика с независимыми ошибками

Каждый кейс создаёт отдельную копию в `.work/`; исходный исправный проект сохраняется. Откройте [описание кейсов](exercises/README.md), затем выполните, например:

```sh
python scripts/prepare_case.py type
cd .work/type
python scripts/validate_spec.py spec/openapi.yaml
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Из второго терминала в **той же копии**:

```sh
python scripts/check_contract.py --spec spec/openapi.yaml --base-url http://127.0.0.1:8001
```

Получите `FAIL` с операцией и JSON-путём. Исправьте контракт в этой копии и повторите **ту же** команду до `PASS`. Для финального кейса потребуется также изменить небольшое правило в `app/rules.py`; после изменения Python-кода остановите и снова запустите сервер. Вводимые данные уникальны для каждого прогона, поэтому контрактную команду можно повторять без очистки хранилища.

## Если что-то не запускается

- `ModuleNotFoundError`: проверьте активное окружение и повторите `python -m pip install -r requirements.txt`.
- Порт занят: остановите прежний сервер сочетанием `Ctrl+C` либо выберите свободный порт в обеих командах.
- `FAIL` из-за недоступного сервера: сначала дождитесь строки `Uvicorn running on ...` и проверьте одинаковый порт.
- После исправления `app/rules.py` перезапустите сервер; изменение YAML читается при следующем запросе к `/openapi.json`, но правило загружается при старте Python-процесса.
- Если упражнение зашло в тупик, создайте новую копию через `--output` с другим путём; исправный исходный контракт остаётся в корне.
